IVFFlat: centroids go stale as the corpus grows

3 stages — build, insert without reindex, rebuild with REINDEX

1. Index built (lists = 100)
Existing chunks get clustered into centroids. Each centroid "owns" the nearby vectors.

At query time, IVFFlat only searches inside the few nearest centroids (ivfflat.probes). If a new vector's true neighborhood has no centroid of its own, it either sits unsearched in the wrong bucket or drags down that bucket's coherence — either way, recall drops. REINDEX throws away the old centroid layout and reclusters every row currently in the table, so the new cluster (panel 3, green) gets its own centroid and becomes findable again.
